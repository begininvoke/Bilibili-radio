# 🎧 Edge 浏览器扩展需求文档：智能省流后台播放助手

## 1. 项目概述
### 1.1 项目背景
在浏览器观看视频（如 B 站、YouTube 等）时，用户仅需听取音频内容。当浏览器标签页处于后台挂起状态时，视频流仍持续加载高清画面，造成不必要的带宽消耗。

### 1.2 核心目标
开发一款适用于 Edge 浏览器的扩展插件，实现"后台纯音频、前台全画质"的智能切换，达到省流目的，并提供优雅的流量监控 UI。

### 1.3 目标用户
- 经常在浏览器中观看视频的用户
- 网络带宽有限的用户（如移动网络、家庭宽带限速用户）
- 注重设备性能和电池续航的用户

## 2. 核心功能模块
### 2.1 智能播放模式切换
**触发机制：**
- 监听浏览器 API `document.visibilityState` 或 `visibilitychange` 事件
- 监听浏览器标签页切换事件

**逻辑规则：**
1. **后台模式：**
   - 触发条件：标签页失去焦点或最小化超过 3 秒（防误触）
   - 动作：
     - 记录当前播放进度
     - 记录当前视频分辨率/画质设置
     - **核心动作：** 尝试切换视频源为"仅音频"或"最低画质"（需针对主流站点做适配，优先通过拦截网络请求修改参数，其次操作 DOM 中的 `<video>` 元素）
     - 暂停视频解码渲染以节省 CPU/GPU 资源

2. **前台模式：**
   - 触发条件：用户切回标签页
   - 动作：
     - 恢复之前记录的画质设置
     - 如果切换了视频源，需在当前进度无缝恢复播放
     - 恢复视频渲染

### 2.2 干扰净化与背景管理
**功能描述：**
自动处理视频播放页面的非必要视觉元素，进一步减少资源占用。

**逻辑规则：**
1. **弹幕控制：**
   - 进入后台：强制隐藏/关闭弹幕层（若无法关闭显示层，则设置 `opacity: 0` 或 `display: none`）
   - 回到前台：恢复弹幕显示状态（如果是用户手动关闭的，则保持关闭，需存储用户偏好状态）

2. **动态背景控制：**
   - 识别页面中的 CSS 动画、Canvas 动画背景、GIF 图片
   - 后台策略：注入 CSS 全局禁用动画 (`animation: none !important`) 或暂停特定 Canvas 绘制
   - 前台策略：移除注入的 CSS，恢复原视觉效果

### 2.3 流量消耗实时监控
**数据采集：**
- 使用 `chrome.webRequest` API（Manifest V3 推荐）或 `chrome.declarativeNetRequest` API
- 监听 `onCompleted` 事件，筛选 `type: "media"` 或特定视频流扩展名 (`.m4s`, `.mp4`, `.m3u8`, `.mpd`) 的请求
- 累计请求的 `responseHeaders` 中的 `Content-Length` 或 `encodedDataLength`
- 处理 Chunked 编码的情况，确保流量统计准确性

**数据存储：**
- 使用 `chrome.storage.local` 存储累计流量数据
- 数据结构：
  ```json
  {
    "totalBytes": number,
    "totalSavedBytes": number,
    "sessions": [
      {
        "url": string,
        "bytes": number,
        "savedBytes": number,
        "timestamp": number,
        "duration": number
      }
    ]
  }
  ```

**UI 展示：**
- 点击插件图标弹出 Popup 页面
- 显示"本次会话节省流量"与"总计消耗流量"
- 实时速率显示
- 流量趋势图表（最近 7 天）

## 3. 界面设计需求
### 3.1 设计风格
- **关键词：** 现代极简、毛玻璃质感、科技感
- **配色：** 深色模式为主，搭配青色/紫色霓虹渐变色作为强调色，契合开发者审美
- **字体：** 无衬线字体，如 Inter 或 SF Pro，确保清晰易读

### 3.2 页面布局
**Popup 窗口 (300px x 450px)**
1. **顶部状态栏：**
   - 显示当前标签页状态：`🟢 前台播放中` / `🌙 后台省流中`
   - 当前模式：`全画质` / `纯音频`
   - 网站图标和名称

2. **核心数据仪表盘：**
   - 设计一个圆环进度条或数字大屏风格的计数器
   - 显示 **"已节省流量"** (估算值：全画质流量 - 纯音频流量)
   - 显示 **"实时下行速率"** (动态跳动数字，带动画效果)
   - 显示 **"本次会话流量"** 和 **"总计流量"**

3. **功能开关区：**
   - Toggle 开关：智能省流模式（默认开启）
   - Toggle 开关：自动净化弹幕/背景（默认开启）
   - Toggle 开关：流量监控（默认开启）

4. **详细日志入口：**
   - 底部一个小的"查看详情"按钮，点击展开最近 5 条视频流请求记录
   - 每条记录包含：时间、网站、流量大小、节省流量

5. **设置页面：**
   - 后台切换延迟时间设置（默认 3 秒）
   - 流量统计周期设置
   - 网站白名单/黑名单设置

## 4. 技术实现细节与约束
### 4.1 技术栈建议
- **框架：** Vue 3 + Vite（推荐，轻量高效，适合浏览器扩展）
- **UI 库：** Tailwind CSS（推荐，便于做精细的高级感样式）
- **状态管理：** Pinia（轻量级状态管理）
- **构建工具：** Vite（快速构建和热更新）
- **Manifest 版本：** Manifest V3（Edge 商店强制要求）

### 4.2 关键技术难点与解决方案
1. **视频源拦截与修改：**
   - **挑战：** 现代视频网站（如 B 站）使用 DASH (`.mpd`) 或 HLS (`.m3u8`) 协议，视频和音频是分片的
   - **解决方案：**
     - 在 `Background Service Worker` 中使用 `chrome.declarativeNetRequest` API（Manifest V3 推荐）
     - 针对 B 站：拦截包含 `fnval` 参数的请求，后台时修改请求参数强制请求仅音频流（通常为最高音质），前台时恢复参数
     - 针对 YouTube：拦截包含 `itag` 参数的请求，后台时修改为仅音频的 itag 值

2. **流量统计准确性：**
   - **挑战：** 需区分"视频流"和"页面其他资源"，且 `Content-Length` 在流式传输中可能不存在
   - **解决方案：**
     - 基于 URL 模式和 MIME 类型双重筛选视频流请求
     - 处理 Chunked 编码的情况，使用 `encodedDataLength` 作为备选
     - 定期清理过期的流量数据，避免存储膨胀

3. **性能约束：**
   - **挑战：** Content Script 过于频繁地操作 DOM 会影响页面性能，后台脚本需轻量化
   - **解决方案：**
     - 使用 `requestAnimationFrame` 优化 DOM 操作
     - 批量处理 DOM 操作，减少重排重绘
     - 后台脚本使用事件驱动模式，避免轮询
     - 使用 `chrome.storage.local` 的批量读写 API，减少存储操作次数

4. **站点适配：**
   - **B站适配：** 拦截 `api.bilibili.com` 和 `upos-sz-mirrorcos.bilivideo.com` 等域名的请求
   - **YouTube适配：** 拦截 `www.youtube.com` 和 `r3---sn-xxxxx.googlevideo.com` 等域名的请求
   - **通用适配：** 对于其他视频网站，尝试使用 DOM 操作切换视频质量

### 4.3 兼容性
- **目标浏览器：** Microsoft Edge (Chromium 内核) 90+ 版本
- **优先适配：** Bilibili (B站)
- **次级适配：** YouTube
- **其他适配：** 支持常见视频网站（如爱奇艺、腾讯视频等）

## 7. 风险评估
### 7.1 技术风险
- **视频网站 API 变更：** 可能导致拦截规则失效
- **浏览器 API 变更：** Manifest V3 相关 API 可能发生变化
- **性能问题：** 在低配置设备上可能影响浏览体验

### 7.2 解决方案
- **建立站点适配规则库：** 定期更新适配规则
- **监控浏览器 API 变化：** 及时调整代码以适应 API 变更
- **性能优化：** 采用轻量化设计，避免过度消耗资源
