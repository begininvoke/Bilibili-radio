# 多 P 视频行内展开与批量入队

## 背景

多 P 视频从搜索结果进入播放队列时，搜索接口返回的视频级 `Track` 通常没有 `cid`。旧逻辑会在真正播放时用 `/api/tracks/<bvid>` 的第一项 `pages[0]` 兜底，导致用户想操作多 P 时经常只播放第一 P。

上一版 hover 弹层不符合当前交互预期，并且在搜索列表里容易出现“正在读取分 P”停留。交互改为显式点击触发。

## 当前交互

- 鼠标移入行不再自动请求分 P，不再弹出浮层。
- 点击行内播放按钮：
  - 如果是多 P 视频级 Track，在该行下方自然展开分 P 列表。
  - 如果是单 P，仍按原行为播放。
  - 已展开时再次点击播放按钮会收起。
- 点击右侧加号：
  - 如果是多 P 视频级 Track，自动把所有分 P 加入播放队列。
  - 如果是普通单曲或已明确 `cid` 的分 P Track，仍只加入当前曲目。
- 展开的分 P 列表支持按需操作：
  - 点击标题播放指定 P。
  - 收藏/取消收藏指定 P。
  - 加入指定 P 到队列。

## 实现要点

- 分 P 展开通过 `GET /api/tracks/<bvid>` 读取详情。
- 前端只缓存读取成功的同 BV 分 P结果，避免旧的未完成请求把 UI 卡在 loading。
- 请求保留 10 秒超时，失败后可以再次点击重试。
- 展开区域在文档流内渲染，不使用绝对定位浮层。
- 分 P 行只展示标题、喜欢、加入队列；不展示封面、作者、时长和歌单选择。
- 播放队列和本地库仍按 `bvid + cid` 精确去重，避免 P1/P2/P3 互相污染。

## 验证

- `npm run type-check`
- `npm run build`
- 本地后端确认 `BV16A4y1D7fW` 可返回 3 个分 P，分别有独立 `cid`、标题和时长。
