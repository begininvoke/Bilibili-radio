# 多 P 视频 Hover 面板与分 P 入队修复

## 背景

用户反馈多 P 视频从搜索结果加入播放队列后仍然只播放第一 P。根因是搜索结果返回的是视频级 `Track`，`cid` 为空；播放器在真正播放时会用 `/api/tracks/<bvid>` 的 `pages[0]` 兜底，因此队列、播放、下载都会落到第一 P。

## 本轮实现

- `TrackRow` 对 `cid == null` 的视频级 Track 做 hover 懒加载：
  - 鼠标移入时请求 `GET /api/tracks/<bvid>`。
  - 若返回多个 `pages`，自动显示固定尺寸分 P 面板。
  - 面板高度固定，内容区域可滚轮滚动。
- 分 P 面板每一项绑定具体 `bvid + cid`：
  - 播放此 P。
  - 加入播放队列。
  - 收藏/取消收藏此 P。
  - 加入所选本地歌单。
- 视频级 Track 的播放按钮和加队列按钮不再直接把多 P 视频送入队列；检测到多 P 时只展开分 P 面板，由用户选择具体 P。
- 本地库和播放队列的同曲判断改为精确分 P：
  - 两边都有 `trackId` 时按 `trackId`。
  - 只要任意一边带 `cid`，就必须 `bvid + cid` 都一致才视为同一首。
  - 只有两边都没有 `cid` 时才按 `bvid` 去重。

## 对用户行为的影响

- 搜索结果里 hover 多 P 视频，会看到 P1/P2/P3 等子项。
- P2/P3 可以独立入队，不再被第一 P 污染。
- 同一个 BV 下的不同 P 可以分别收藏和加入歌单。
- 单 P 视频仍保持原有点击播放、加队列行为。

- `npm run type-check` 通过。
- `npm run build` 通过。
- 本地后端接口验证 `BV16A4y1D7fW` 返回 3 个分 P，分别包含独立 `cid`、标题、时长和封面。
