# B站视频播放器仿网易云：前端任务拆解

## 1. 核心方向

本项目前端不是靠堆粉色、玻璃拟态、卡片和动画制造高级感，而是先建立统一视觉系统，只在最重要的播放场景保留一个标志性动态效果。

目标体验：

- 像网易云桌面客户端一样熟悉、安静、沉浸。
- 明确属于 B站内容生态，而不是普通音乐播放器。
- 二次元气质要轻，放在细节里，不压过内容和播放体验。

风格关键词：

- 清爽
- 沉浸
- 轻二次元

唯一视觉记忆点：

- 播放详情页的动态封面氛围背景。

明确禁止：

- 不做蓝紫 AI 渐变。
- 不做满屏粉色。
- 不做满屏玻璃拟态。
- 不让所有卡片漂浮。
- 不给每个组件都加动画。
- 不把首页做成视频网站瀑布流。
- 不直接堆动漫角色图。

## 2. 视觉优先级

页面只允许有三层视觉重心。

第一层：当前播放内容

- 当前视频封面。
- 视频标题。
- UP 主。
- 播放控制。
- 播放进度。
- 播放详情页。

第二层：内容选择

- 推荐内容。
- 搜索结果。
- B站收藏夹。
- 本地歌单。
- 最近播放。

第三层：辅助功能

- 消息。
- 设置。
- 换肤。
- 登录。
- 更多操作。

实现要求：

- 播放按钮和当前播放内容必须最醒目。
- 搜索、导航、设置、装饰元素都要主动降级。
- 不允许多个区域同时争抢注意力。

## 3. 第一阶段：应用骨架

目标：先完成网易云式桌面播放器结构，不做高级动效，不做 Shader。

组件任务：

- `AppShell`
  - 建立全局布局容器。
  - 固定左侧导航、顶部工具栏、底部播放器。
  - 中间内容区自适应。
- `Sidebar`
  - 宽度 `220px`。
  - 只做扁平导航，不放卡片。
  - 当前选中项使用浅粉背景、粉色图标、左侧 3px 指示线。
- `TopBar`
  - 高度 `56px`。
  - 包含搜索框、登录头像、换肤、消息、伪窗口按钮。
  - 视觉权重低于底部播放器。
- `MainContent`
  - 使用统一内边距 `24px 32px`。
  - 区块间距 `32px`。
  - 不做 Landing Page 式大留白。
- `PlayerBar`
  - 高度 `80px`。
  - 永远固定底部。
  - 作为全应用最高优先级组件。
- `QueueDrawer`
  - 默认收起。
  - 展开宽度 `320px`。
  - 从右侧滑入。
  - 不挤压底部播放器。

验收标准：

- 页面在无业务数据时也有稳定桌面客户端结构。
- 底部播放器始终可见。
- 左侧导航、中间内容、顶部工具栏、底部播放器边界清晰。
- 没有 Shader、复杂 Motion 动画和大量装饰。

## 4. 第二阶段：设计系统

目标：统一颜色、字号、间距、圆角、阴影、Hover 和深色模式，避免不同组件各自生成风格。

必须建立全局 CSS Token：

```css
:root {
  --color-primary: #fb7299;
  --color-primary-hover: #f45f8b;
  --color-primary-soft: #fff0f5;

  --color-bg-app: #f5f6f8;
  --color-bg-sidebar: #f8f8fa;
  --color-bg-content: #ffffff;
  --color-bg-hover: #f4f4f5;

  --color-text-primary: #18181b;
  --color-text-secondary: #71717a;
  --color-text-tertiary: #a1a1aa;

  --color-border: #e4e4e7;

  --radius-small: 8px;
  --radius-medium: 12px;
  --radius-large: 16px;

  --shadow-popup: 0 12px 32px rgba(0, 0, 0, 0.12);

  --player-height: 80px;
  --sidebar-width: 220px;
}

[data-theme="dark"] {
  --color-bg-app: #151517;
  --color-bg-sidebar: #19191c;
  --color-bg-content: #202024;
  --color-bg-hover: #2a2a2f;

  --color-text-primary: #f4f4f5;
  --color-text-secondary: #a1a1aa;
  --color-text-tertiary: #71717a;

  --color-border: #34343a;
  --color-primary-soft: rgba(251, 114, 153, 0.14);
}
```

卡片使用规则：

- 可以是卡片：推荐视频封面、收藏夹封面、本地歌单、登录弹窗、空状态引导。
- 不做卡片：搜索结果列表、最近播放列表、播放队列、左侧导航、页面标题、底部播放器。

交互规则：

- 普通 Hover 使用 `transition: 160ms ease`。
- Hover 背景用浅灰。
- 当前播放项用浅粉。
- 阴影只用于弹窗、抽屉，不用于每个内容块。

验收标准：

- 颜色只来自 Token。
- 圆角不随组件随意变化。
- 页面不呈现大面积单一粉色。
- 暗色模式可切换且层级清楚。

## 5. 第三阶段：页面内容

目标：把内容页从“视频网站卡片流”改成“桌面播放器内容选择”。

首页任务：

- 顶部只放轻量欢迎语，例如“下午好，继续看看上次的内容吧”。
- 不做巨大 Hero。
- 第一屏优先展示：
  - 继续播放。
  - 最近播放。
  - B站收藏夹快捷入口。
- 第二屏展示：
  - 为你推荐。
  - 本地歌单。
  - 热门视频。
- 视频卡片一行 4 到 5 个。
- 卡片只显示封面、标题、UP 主、时长。
- 播放量等次要信息放到 Hover 或详情中。

搜索结果页任务：

- 改为网易云式紧凑行列表。
- 行结构：

```text
序号 | 封面 | 视频标题 / UP主 | 时长 | 播放量 | 操作
```

- 行高约 `64px`。
- 默认无边框。
- Hover 用浅灰背景。
- 当前播放用浅粉背景。
- 操作按钮默认弱化，Hover 后增强。
- 双击整行播放。

收藏夹页任务：

- 收藏夹列表可以用封面卡片。
- 收藏夹内容页使用紧凑行列表。
- 支持“导入为本地歌单”的入口。

歌单详情页任务：

- 左侧可显示歌单封面和基础信息。
- 右侧主体使用歌曲/视频列表。
- 不做大面积卡片堆叠。

最近播放页任务：

- 使用列表，不使用卡片。
- 支持按时间分组可后续再做。

验收标准：

- 首页不像视频网站瀑布流。
- 搜索、最近播放、队列都保持列表密度。
- 内容页服务于播放选择，而不是展示炫技。

## 6. 第四阶段：播放器交互

目标：重做底部播放器和播放队列，这是整个前端最重要的交互区域。

底部播放器布局：

- 左侧 30%：当前内容。
- 中间 40%：核心控制。
- 右侧 30%：辅助操作。

左侧任务：

- 48px 当前封面。
- 标题。
- UP 主。
- 喜欢按钮。
- 打开播放详情页按钮。
- 标题和 UP 主最多两行。

中间任务：

- 第一行：

```text
随机/循环 | 上一首 | 播放 | 下一首 | 播放模式
```

- 第二行：

```text
当前时间 | 进度条 | 总时间
```

- 播放按钮 `40px` 到 `44px`。
- 播放按钮使用实心 B站粉。
- 上一首和下一首保持普通图标按钮，不做成大粉色按钮。

右侧任务：

- 音量。
- 字幕。
- 画中画。
- 播放队列。
- 全屏。
- 低优先级按钮只显示图标，不常驻文字。

播放队列任务：

- 当前播放项浅粉背景。
- 非当前项弱化。
- 支持点击播放。
- 支持删除队列项。
- 拖拽排序放到后续，不作为第一版阻塞项。

验收标准：

- 用户第一眼能定位当前播放内容和播放按钮。
- 进度条可读、可拖动。
- 队列抽屉不破坏主布局。
- 播放器比所有内容卡片更有存在感。

## 7. 第五阶段：播放详情与品牌动效

目标：最后才加入黑胶、唱针、封面切换和 Shader，确保它们是品牌记忆点，而不是视觉噪声。

播放详情页任务：

- 全屏沉浸布局。
- 背景由当前封面生成：
  - 模糊封面背景。
  - 低频流动 Shader。
  - 深色半透明遮罩。
- 前景显示：
  - 黑胶唱片。
  - 唱针。
  - 视频标题。
  - UP 主。
  - 右侧信息区。

右侧信息区不照搬歌词页，改为 B站内容结构：

```text
字幕 | 简介 | 章节 | 弹幕精选
```

没有字幕时默认显示简介。

标题信息：

```text
视频标题
UP主 · 分区 · 发布时间
播放量 / 点赞 / 收藏
```

Shader 限制：

- 只允许用于播放详情页背景。
- 不放在搜索页、收藏夹页、设置页、登录弹窗、视频卡片。
- 动画速度非常慢。
- 不使用高饱和蓝紫色。
- 背景整体降低亮度。
- 鼠标移动只产生轻微形变。
- 不出现明显粒子。
- 不影响标题、字幕、简介阅读。

建议参数：

- 动画速度：`0.08` 到 `0.15`。
- 模糊：`40px` 到 `80px`。
- 背景缩放：`1.1` 到 `1.2`。
- 遮罩透明度：`45%` 到 `65%`。
- 鼠标影响半径较大，但形变幅度很小。

降级方案：

```css
background:
  linear-gradient(rgba(0, 0, 0, 0.55), rgba(0, 0, 0, 0.7)),
  var(--current-cover);
background-size: cover;
filter: blur(...);
```

验收标准：

- 暂停时黑胶停止旋转。
- 播放时黑胶旋转。
- Shader 不抢文字可读性。
- Shader 失败时页面仍可正常展示。

## 8. 二次元细节任务

目标：用 5% 到 10% 的视觉占比表达轻二次元，不破坏清爽播放器基调。

可做项：

- Logo 使用电视机、猫耳、播放按钮组合。
- 空状态使用原创小电视助手。
- Loading 使用跳动弹幕点。
- 收藏夹标签使用轻量贴纸造型。
- 当前播放状态使用粉色音频波形。
- 封面 Hover 出现圆形播放按钮。
- 页面标题旁偶尔使用星星、弹幕或音符线稿。
- 二维码登录弹窗放简单小助手插图。

禁止项：

- 不把动漫人物当页面主体。
- 不让贴纸、图标、动效覆盖核心内容。
- 不在每个页面都做强装饰。

## 9. 状态设计任务

Loading：

- 列表骨架。
- 卡片骨架。
- 播放器封面骨架。
- 二维码加载状态。

Empty：

- 未登录。
- 收藏夹为空。
- 最近播放为空。
- 搜索无结果。
- 播放队列为空。

Error：

- 登录过期。
- 视频失效。
- 视频无法解析。
- 网络错误。
- 收藏夹加载失败。

错误展示规则：

- 页面级错误放页面内。
- 短暂操作失败才使用 Toast。
- 不允许大量错误直接弹 Toast。

## 11. 最终比例

前端视觉比例按下面控制：

- 85% 清晰桌面播放器设计。
- 10% 轻二次元细节。
- 5% Shader 品牌效果。

这份任务拆解的核心约束是：先完成静态布局和设计系统，再做微交互，最后才加 Shader。

# **补充**

1. **模糊背景单独分层**
    不要直接给页面容器写 `filter: blur()`，否则文字也可能被模糊。用伪元素或独立背景层：

```
.player-bg {
  position: absolute;
  inset: -40px;
  background:
    linear-gradient(rgba(0, 0, 0, 0.55), rgba(0, 0, 0, 0.7)),
    var(--current-cover) center / cover;
  filter: blur(50px);
  transform: scale(1.1);
}
```

1. **增加性能降级**
    除了 Shader 加载失败，还应在移动端、低性能设备、`prefers-reduced-motion` 下直接使用静态模糊封面。
2. **每轮增加验收条件**
    例如第一轮要求布局无溢出，第二轮要求无随机颜色和圆角，第四轮要求播放状态只有一个 Store 管理。这样 Agent 不容易只“写完代码”却没有真正完成效果。
