# UP 点击解析页与 80% 播放计数

日期：2026-08-08

## 问题

UP 名 hover 能高亮，但点击后仍可能没有进入 UP 主页。原因是旧 Track 数据可能缺少 `ownerMid`，此前点击时会在原页面等待 `/api/tracks/<bvid>` 解析 mid；如果解析慢或失败，用户看到的就是“点了没反应”。

播放次数此前在音频流加载成功后立即调用 `addRecent`，导致只点一下歌也会增加播放次数。

## 调整

- UP 点击：
  - 有 `ownerMid` 时直接进入 `/up/<mid>`。
  - 没有 `ownerMid` 时先进入 `/up/resolve/<bvid>`。
  - UP 页面负责显示加载状态，并通过 BV 详情解析真正的 UP mid。
  - 解析失败会在 UP 页面展示错误，不再停留在原页面静默失败。
- 播放次数：
  - 移除播放开始时的 `addRecent`。
  - 前端累计实际播放时间，达到总时长 80% 后才记录最近播放并增加播放次数。
  - 直接拖进度条到 80% 不计数，因为没有累计实际听满 80%。
  - 自然播放结束会记录为 completed。
  - 记录时会传 `positionMs`、`listenMs`、`completed` 给后端。

## 后续

后端已有播放事件服务也能做更完整的会话统计。后续可以把前端的 80% 最近播放记录统一切到 `/api/playback/events`，让播放次数、跳过、完成率全部从同一套会话事件派生。
